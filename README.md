# Розалия — ресторан современной кухни

Демонстрационный статический сайт для показа заказчику. HTML5, CSS3 и чистый JavaScript с ES-модулями. Устанавливать зависимости или запускать сборщик для сайта не нужно.

Репозиторий: [mansiks1/restaurant-site-demo](https://github.com/mansiks1/restaurant-site-demo), **приватный**. GitHub Pages пока не включён. Публикация и изменение видимости допускаются только после явного слова заказчика **«публикуем»**. Настройка `site_url` в CMS и адреса в sitemap — подготовка к публикации, а не подтверждение работающего публичного сайта.

Ресторан «Розалия»: белый фон #FFFFFF, основной текст #1F2430, золотистый акцент #C9A66B и линии #E5E5E5. Текст набран Montserrat, текстовый логотип — Marck Script. Оба семейства поддерживают кириллицу. Все SVG-иконки, изображения-заглушки и оформление созданы для этого проекта.

**Демо, не действующий ресторан.** Адрес, телефон, почта, цены и события вымышлены. Заявки и звонки не принимаются. Все изображения — локальные художественные WebP-заглушки с явными подписями. Перед запуском замените их реальными данными и фотографиями с разрешением на использование.

## Быстрый запуск

Откройте PowerShell в корне этого репозитория:

```powershell
py -m http.server 8000 --bind 127.0.0.1
```

Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/). Альтернатива — любой статический HTTP-сервер. Через `file://` ES-модули и `fetch()` не работают.

Для просмотра на телефоне в одной локальной сети запустите сервер с `--bind 0.0.0.0` и откройте `http://IP-ВАШЕГО-ПК:8000/`. Доступность зависит от брандмауэра и сети; не включайте локальный CMS-прокси на публичном интерфейсе.

## Контент без сборщика

Блюда читаются из `content/menu/dishes.json`, ключ `dishes`. Категории — из `content/menu/categories.json`. События, статьи и страницы по-прежнему читаются из Markdown с YAML front matter через `fetch()`. Шаблоны деталей используют `events/event.html?slug=autumn-dinner` и `blog/post.html?slug=taste-of-autumn`. Slug совпадает с именем Markdown-файла без `.md`. Неизвестный slug показывает понятное сообщение и ссылку обратно.

YAML разбирается с JSON schema: даты остаются строками. Markdown преобразуется в HTML и очищается DOMPurify; HTML из редактора не выполняется как скрипт. Ссылки на изображения ограничены локальной папкой `assets/img/`.

Для событий и журнала локальный и приватный просмотр использует список файлов `content/index.json`. После **добавления, переименования или удаления Markdown-файлов этих разделов** обновите список и sitemap:

```powershell
node tools/update-index.mjs
node tools/verify.mjs
```

Изменения меню, включая добавление и удаление блюд внутри JSON, видны после обновления страницы без индекса и без GitHub API. Изменения текста существующих Markdown-файлов также не требуют обновления индекса. Для новых событий и статей на публичном `mansiks1.github.io` новые файлы обнаруживаются через GitHub Trees API. Токен посетителям не передаётся. Индекс кешируется в рамках вкладки на две минуты; после сохранения в CMS дождитесь обновления Pages и кеша. При недоступности API или превышении его лимита используется индекс из репозитория: недавно добавленные записи могут временно не появиться. Поддерживайте `content/index.json` актуальным для надёжного резервного списка. Если переносите сайт на другой домен или аккаунт, обновите условие обнаружения в `assets/js/content.js` либо используйте актуальный файловый индекс.

`.nojekyll` сохраняет Markdown как исходные файлы при публикации GitHub Pages — удалять его нельзя. Все ссылки и пути работают как в корне локального сервера, так и в `/restaurant-site-demo/`.

## Что и где редактировать

| Раздел | Файлы | Основные поля |
| --- | --- | --- |
| Категории | `content/menu/categories.json` | `id`, `title`, `description`, `order` |
| Блюда | `content/menu/dishes.json`, список `dishes` | `id`, `title`, `category`, `price`, `description`, `image`, `image_alt`, `order`, `available` |
| События | `content/events/*.md` | `title`, `date`, `kind`, `price`, `description`, `image`, `image_alt`, Markdown body |
| Журнал | `content/blog/*.md` | `title`, `date`, `category`, `description`, `image`, `image_alt`, Markdown body |
| Страницы | `content/pages/*.md` | Заголовок, вступление, текст и специальные поля страницы |

`price` — число без ₽ и пробелов: `1290`. На сайте оно станет `1 290 ₽`. `available: false` сохраняет блюдо с пометкой «Сейчас нет в наличии». Время чтения статьи считается автоматически по тексту из расчёта 160 слов в минуту.

События задавайте датой и временем с явным смещением, например `2026-10-24T19:00:00+03:00`. Календарь, отметка текущего дня и отображение времени используют Москву (`Europe/Moscow`). Если редактор находится в другом часовом поясе, проверьте сохранённое время начала. Дата статьи — `2026-10-20`, без времени.

Для настоящих контактов замените адрес, номер и почту в `contacts.md`, затем установите `demo: false`: появятся ссылки для звонка и письма. Измените также текст о демонстрационном проекте в контенте и подвале перед передачей реальному ресторану. Карта остаётся заглушкой по ТЗ.

## Меню: порции и безопасный текст

Все 12 существующих блюд сохранены в одном JSON. Пример структуры:

```json
{
  "dishes": [{
    "id": "truffle-pasta",
    "title": "Паста с трюфелем",
    "category": "mains",
    "price": 890,
    "description": "Тальятелле, сливочный соус и чёрный трюфель.",
    "image": "assets/img/pasta.webp",
    "image_alt": "Фото: паста с трюфелем, заглушка",
    "order": 1,
    "available": true
  }]
}
```

JSON загружается один раз, карточки добавляются в DOM порциями по 12. Следующую порцию вызывает `IntersectionObserver` для `#menu-sentinel` с `rootMargin: '200px'`. Пока остались блюда, доступна также кнопка «Показать ещё» для клавиатуры и браузеров без observer. В текущих данных ровно 12 блюд; тест 12 → 24 → 25 выполнен на временном наборе, который не входит в меню.

Поиск работает по всему списку, сбрасывает выборку и курсор порций. Переход к ещё не выведенной категории догружает необходимые порции перед переходом по якорю. Карточки получают `.reveal`, затем `.is-visible` при появлении в зоне просмотра. При `prefers-reduced-motion: reduce` карточки показываются сразу без движения; изменения настройки также учитываются.

Пути JSON заданы через `new URL('../../content/menu/dishes.json', import.meta.url)` и аналогично для категорий. Названия, описания, подписи и категории из редактора присваиваются через `textContent`; разметка из полей меню не исполняется.

## Шапка, hero и контакты

На десктопе от 1024 px шапка состоит из трёх колонок: контакты, логотип высотой 66 px, адрес. Ниже — линия и навигация. На меньшей ширине под логотипом всегда видны четыре ссылки: на планшете в строку, на телефоне в два ряда. Контакты доступны по ссылке «Контакты», галерея и журнал — в подвале. Высота шапки и отступ закреплённой панели категорий согласованы через CSS-переменные.

Шапка читает объект `contacts` из `assets/js/content.js`. Он содержит значения по умолчанию; после загрузки контактной Markdown-страницы объект синхронизируется с полями CMS, чтобы адрес и телефон совпадали в шапке, подвале и на контактах. На главной добавлена кнопка «Частные мероприятия», ведущая к контактам.

Внутренние hero имеют высоту 380 px на десктопе и 260 px до 1024 px. Файл `assets/img/hero-placeholder.webp` — собственная художественная заглушка. **Замените на фото ресторана**. Тёмный слой задан как `rgba(0,0,0,0.45)`; крестики и контактные иконки нарисованы вручную в SVG.

Светлый акцент #C9A66B используется в линиях, декоре и заливке кнопок. Для золотистого текста, включая цены, используется более тёмный #806034: исходный светлый акцент на белом не обеспечивает требуемые 4,5:1. Проверенные текстовые пары дают не менее 4,98:1.

## Админ-панель Decap CMS

Открывается по `/admin/` относительно сайта: локально [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/), после публикации — `/restaurant-site-demo/admin/`. Файл конфигурации загружается относительно этой папки, что важно для GitHub Pages.

Настроены пять коллекций: блюда (file collection с полем-списком `dishes`), категории меню, события, журнал и страницы. У всех полей есть русские подсказки. Категория блюда выбирается из JSON-списка; ID категорий проверяются на уникальность. Изображения загружаются в `assets/img/uploads`; выбирайте WebP до 2 МБ и заполняйте подпись/alt.

**Рабочий вход через GitHub OAuth ещё не подключён.** Загрузка панели и конфигурации проверена, вход редактора и сохранение через удалённый backend не проверялись. Перед передачей админки заказчику требуется отдельный шаг настройки авторизации. Сам по себе статический GitHub Pages не выполняет серверный обмен OAuth-кодом.

Вариант с GitHub OAuth:

1. Выберите совместимый OAuth-посредник из [документации Decap](https://decapcms.org/docs/external-oauth-clients/) и разместите его на HTTPS-сервере.
2. Создайте GitHub OAuth App. Укажите callback URL, который требует выбранный посредник. Сохраните Client Secret только в серверных переменных окружения.
3. В `admin/config.yml` добавьте `backend.base_url` и `backend.auth_endpoint` из настроек посредника, сохранив `name: github`, репозиторий и ветку `main`.
4. Выдайте редактору право push в репозиторий. Выполните вход, сохраните тестовую правку, проверьте коммит и отображение результата на сайте.

Альтернативный маршрут через сервис вроде Netlify Identity/Git Gateway требует отдельного выбора сервиса, проверки его доступности и смены backend по [документации Git Gateway](https://decapcms.org/docs/git-gateway-backend/). Наличие этого маршрута в документации не означает, что он уже настроен в проекте. Не помещайте Client Secret или GitHub-токен в HTML, JavaScript и публичный config.yml.

Для локального редактирования без удалённого OAuth:

```powershell
# Во втором окне PowerShell, из корня репозитория:
$env:BIND_HOST = '127.0.0.1'
npx decap-server
```

Затем откройте локальный `/admin/`. `local_backend: true` уже задан. Этот режим пишет файлы на диске; после добавления событий или статей запустите `node tools/update-index.mjs`, проверьте изменения и сделайте отдельный коммит. Прокси запускается только по этой команде и не требуется посетителям. Подробнее: [Decap Proxy](https://decapcms.org/docs/decap-proxy/).

## Проверки

```powershell
node tools/verify.mjs
Get-ChildItem assets/js -Filter *.js | ForEach-Object { node --check $_.FullName }
node --check admin/admin.js
git diff --check
```

Node нужен только для вспомогательных проверок и обновления индекса; браузерный сайт не требует Node. Результаты проверки браузером и чек-лист ТЗ — в [QA.md](QA.md). Проверено 45 сочетаний страницы и ширины: 360, 390, 768, 1024 и 1280 CSS px. На каждой посетительской странице один h1, нет горизонтальной прокрутки, у изображений заданы alt, размеры и lazy loading.

## Зависимости

- Google Fonts: Montserrat (300–700) и Marck Script (400), `display=swap`. Кириллица подтверждена в официальных метаданных [Montserrat](https://github.com/google/fonts/blob/main/ofl/montserrat/METADATA.pb) и [Marck Script](https://github.com/google/fonts/blob/main/ofl/marckscript/METADATA.pb).
- Decap CMS 3.17.1 — закреплённая версия с jsDelivr, только в админке.
- Локальные js-yaml 5.5.0, marked 18.1.1, DOMPurify 3.4.17. Лицензии находятся в `assets/js/vendor/`.

Интернет нужен для Google Fonts и админки. При недоступности шрифтов работают системные запасные семейства. Все изображения и парсеры контента хранятся в репозитории.

## Публикация — только после «публикуем»

На этапе сдачи выполнена только отправка исходников в приватный репозиторий. После явного разрешения:

```powershell
gh repo edit mansiks1/restaurant-site-demo --visibility public --accept-visibility-change-consequences
gh api -X POST repos/mansiks1/restaurant-site-demo/pages -f "source[branch]=main" -f "source[path]=/"
```

Далее нужно дождаться успешного состояния Pages и проверить публичный адрес `https://mansiks1.github.io/restaurant-site-demo/`. При публикации публичными станут исходники и история коммитов. После разрешения публикации обновите статус в README отдельным коммитом. Правки выполняются отдельными логическими коммитами.
